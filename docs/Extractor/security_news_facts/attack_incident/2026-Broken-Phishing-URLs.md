# Broken Phishing URLs

## 摘要

钓鱼攻击者使用格式错误的 URL 参数来绕过安全检测系统，浏览器会忽略无效参数但安全工具会被干扰。

## 事实内容

安全研究员 Xavier Mertens 报告了一种新型钓鱼活动，攻击者利用故意构造的格式错误 URL 参数来规避安全检测系统。

**攻击技术**：
标准 URL 语法使用 `name=value` 格式，参数间用 `&` 分隔。观察到的恶意 URL 在合法参数后附加无效字符，例如 `&*(Df` 而非正确的参数格式。

**样本 URL**：
- hxxps://cooha0720[.]7407cyan[.]workers[.]dev/?dC=handlers@isc[.]sans[.]edu&*(Df
- hxxps://calcec7[.]61minimal[.]workers[.]dev/?wia=handlers@isc[.]sans[.]edu&*(chgd

**攻击原理**：
浏览器通常会忽略格式错误的参数，允许恶意网站正常加载。然而，这种技术会破坏依赖于一致 URL 格式的安全控制措施。

**安全影响**：
如 Mertens 所述："威胁行为者实施此技术来破坏安全控制"，包括：
- 基于正则表达式的检测
- URL 规范化程序
- IOC 提取管道

这种混淆使自动化威胁检测变得更加困难。

**应对措施**：
安全团队可以使用正则表达式模式来提取和分析最终参数，但防御者必须调整检测逻辑以应对故意构造的格式错误 URL 语法。

## 受影响系统

- 基于正则表达式的 URL 检测系统
- URL 规范化工具
- 自动化 IOC 提取管道
- 电子邮件安全网关
